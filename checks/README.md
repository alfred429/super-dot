# A short SuperDot walkthrough

Version: 1.2.0 · 2026-10-31

Use harmless fictional/demo information. This is a practical rehearsal, not an extensive test suite.

1. **Start:** point the Dot at the README and setup plan. It should create/reuse the chosen personal
   vault, read the ten principles and show Personal, Family, Work, Hobbies, Money and Wellbeing.
2. **Remember:** ask “Note it: I'd like to learn wildlife photography.” Inspect the Hobbies note,
   retrieve it, correct a detail and confirm the correction. A retried request should not duplicate it.
3. **Reflect:** draft an evening entry from the chosen note and one user reflection. Show a morning
   starter. Source gaps and assistant suggestions should be clear; feelings come from the person.
4. **Make progress:** create a small project from the supplied Markdown files. Find its goal/next
   action. Make a personal edit, then confirm subsequent setup doesn't overwrite it. If wanted,
   demonstrate one already-connected tool with an authorised harmless result.
5. **Handle waiting:** make the Mac unavailable. The assistant should distinguish receipt/pending
   from a saved vault note. If a durable native task exists, inspect it; otherwise say how to retry.
   Reconnect, inspect the destination and resume without duplicating a completed action.

Record only the useful result or blocker in the personal README. For a chosen native routine,
inspect the saved schedule/timezone and actual output before calling it working. Skip account actions
that haven't been authorised; the documentation remains useful without signing up to every service.

For upkeep, inspect the proposed [SCHEDULE.md](../SCHEDULE.md) without activating tasks. A rehearsal
can use fictional reports; never delete files, restructure live Notion or edit project instructions
merely to demonstrate maintenance.

**Build status:** the 52 Markdown files are the deliverable. Dot/Mac/iPhone execution, connected
accounts and private API-secret capture are not established by writing or inspecting these files.
This walkthrough has not been run on a real Dot in this build. Ordinary document checks cover
file inventory, links, skill metadata and consistency; no live data or credentials are needed.
