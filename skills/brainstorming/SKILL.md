# Brainstorming

Adapted from [Superpowers](https://github.com/obra/superpowers);
[MIT notice](../../licenses/superpowers.txt).

## Inputs and context

Read the idea, intended outcome, constraints and relevant existing project. Use information already
provided before asking questions. This is a conversation skill; Mac access is needed only when
reading or saving local material. For local work, follow the [macOS guidance](../../references/README.md#macos-and-skill-writing-standard).

## Workflow

- If the request is already clear and small, help directly rather than forcing an interview.
- For an open idea, ask the one question most likely to change the direction. Offer a concrete
  starting suggestion when the person is stuck.
- Where a meaningful choice exists, compare two or three real approaches with their practical
  tradeoffs. Recommend the simplest one that fits; omit invented alternatives.
- Converge on a compact concept and one useful experiment or next action. Respect the person's
  decision to skip further exploration or choose a different approach.

## Result and boundaries

Return a useful direction, the important unresolved choice and the next practical action.
For sustained work, record the chosen direction in the existing project or use the
[project starter](../../templates/project/PROJECT.md) when appropriate. A clear reply may be enough;
do not create extra planning documents by default. Discussion alone grants no authority to publish,
spend, contact others or start additional work.
