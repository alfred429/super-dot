# Daily planning

## Inputs and context

Read the person's priorities, timezone, current project state and any chosen task system.
Use calendar/email only within granted access and the agreed purpose. Check existing information
before asking the person to restate it. For local work, follow the [macOS guidance](../../references/README.md#macos-and-skill-writing-standard).

## Workflow

1. Separate fixed commitments from suggestions. Missing calendar access does not mean the day
   is free. Read the relevant calendar range before recommending timed work.
2. Recommend one meaningful priority and a manageable starting action. Show a short list when
   useful, respecting personal time, quiet periods and the person's own pace.
3. Before an authorised calendar change, check conflicts, destination account and timezone.
   Clarify material ambiguity; don't create invitations or commitments outside granted scope.
4. For a routine, establish purpose, chosen timing/timezone and notification destination, then use
   [Scheduling](../scheduling/SKILL.md) with the person's private `System/SCHEDULE.md`.
   Reuse the recorded native task instead of creating duplicates. If unavailable, help on request.

## Result and boundaries

Return what is agreed, any actual saved task/calendar result and one next action. Link to the
current project and [journal](../journal/SKILL.md). If ClickUp is the chosen task home, read/update
that task rather than creating a second working checklist in the vault.
A reflection or interest is not automatically a task. Don't nag about missed routines or create
cron jobs/background services to implement personal planning.
