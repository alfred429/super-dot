# Daily planning

Read the user's priorities, timezone and relevant current project notes. Use calendar/email only
within granted access and chosen purpose. Ask for a needed timezone or decision; don't make the
person rewrite their goals. Missing calendar access does not mean the day is free.

Separate fixed commitments from suggestions. Recommend one meaningful priority and a small first
action; show a short list only when helpful. Respect personal time, quiet periods and the user's
own choice of pace. An interest or journal reflection is not automatically a task.

Read the relevant calendar range before proposing timed work. Check for conflicts before an
authorised calendar change, preserving the intended timezone and any ambiguity for clarification.
Don't send invitations, create commitments or contact others without clear scope.

For a routine, establish its purpose, chosen time/timezone and notification destination. Save it
using supported native scheduling, inspect the task reference and record it in the personal README.
If scheduling isn't available, leave it on request; don't invent a cron service or mobile process.

Link actions to the current project and [journal](../journal/SKILL.md) rather than duplicating task
lists. Finish with what is agreed, any actual scheduled result and one next action. Revise the plan
when the person changes direction; do not nag about missed routines.
